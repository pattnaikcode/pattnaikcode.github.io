How I run incidents and operations

The same lifecycle runs through my support leadership and through the tools I build.

  1. Detect

    Monitoring, alerts and business signals catch problems before clients do.

  2. Diagnose

    From symptoms to cause across logs, FIX messages, queues and databases.

  3. Restore

    Service first, with the safest change, then the root cause.

  4. Communicate

    Clear impact, actions and next update time for every audience.

  5. Prevent

    RCA, corrective actions, runbooks and controls that stop repeats.

OpsPilot

Live demo

Independent project · Incident simulation and operations training platform · 2026

A platform for practising production incidents: model a system, inject controlled faults, and troubleshoot them in a sandbox. Scenarios cover payments messaging, exchange trading, e-commerce and fraud monitoring.

  • Built a system designer and simulator where teams model a system, inject controlled faults and watch how they spread.
  • Built timed failure scenarios with alerts, symptoms and a business cut-off, packaged as reusable scenario packs.
  • Built a Linux lab with log archives, file inspection, network checks and command history.
  • Built scoring and debriefs on detection, diagnosis and recovery, backed by 260+ passing automated tests.
  • Prototyped an AI copilot for support. It uses keyword matching and predefined responses today; LLM and retrieval-based assistance are planned.
